# SEGS.mq5 v3.82 — consolidated active rows and execution timestamps

The screenshot shows four active advisor positions at the same entry/SL, but each displayed row says one leg. v3.81 could not recover an explicit SEGS setup ID from some older comments and therefore used each position ID as its display-group key. This produced repeated identical ACTIVE ENTRY rows.

v3.82 combines legacy advisor positions at the same broker-formatted entry, direction and magic number into one display price row, including an accurate position/leg count and actual SL range if stops differ. This is visual aggregation only: it does not merge execution identities, change set capacity, move stops or targets, or close positions. Distinct known setup IDs remain separate even at identical prices, with numbered rows so they do not look like an accidental duplicate. Opposite directions and exact broker symbols remain separate.

Each active row now includes EXECUTED: YYYY.MM.DD HH:MM EDT/EST underneath it. The time comes from the earliest opening time among the actual broker positions represented by the row and is converted with the EA's Toronto time formatter. It is not the current clock, signal approval time or attachment time. Where a legacy price row includes fills in different displayed minutes, FILLS: first timestamp to last timestamp is shown instead of pretending that several unknown historical setups had one execution time. Missing old setup IDs prevent reliable reconstruction of a closed first leg's original signal time; the displayed interval is explicitly based on the still-open broker fills.

The panel allocates one or two active row/time pairs dynamically and removes stale row/time objects when trades close. This avoids reserving duplicate rows for one grouped legacy entry. If more than two groups exist, the HUD explicitly says that it is showing two. Existing ACTIVE vs NEXT PLANNED separation, independent second setups, direction/reversal checks and bounded dual stops remain intact.
