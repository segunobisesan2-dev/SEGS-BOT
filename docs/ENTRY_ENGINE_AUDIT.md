# Entry audit (before modification)

Baseline: all twelve MQ5 files and the TypeScript payload contain the same 18,217-line MT5/MQL5 EA. Canonical filename is v3.75; older filenames are compatibility aliases. Standard MT5 Trade library is the only external code dependency.

| Area / conflict in baseline | Resolution to implement |
|---|---|
| OnTick/OnTimer → one-second RunAdvisorStrategyEngine → ScanMarketStructureAndAdvice → several CheckAndAutoTradeAdvice calls → ExecuteAdvisedTrade. Z/button also calls ExecuteAdvisedTrade. Five-second inner throttle already bypasses viable signals; outer one-second scan still misses short touches. | Separate discovery from per-tick monitoring. Optional precision engine exclusively owns advisor entries when selected, including Z/button routing. Legacy strategy continues its analysis/display but cannot place competing advisor orders. |
| M30/configurable parent and H1 scanners use origin candle plus two displacement candles, optional BOS, FVG, historical touches and close invalidation. Detection arrays rebuild. confirmTime records the confirmation candle OPEN. Sweep-only detection also compares old origins to today's PDH/PDL/PWH/PWL. | Retain scanner; freeze a separate setup record at actual eligibility time, correct confirmation availability to candle end. New engine conservatively admits only the existing displacement/BOS branch, excluding sweep-only historical classifications that can change with today's liquidity levels. This is an explicit narrower eligibility assumption, not a replacement detector. |
| Lower-TF confirmation sometimes falls back to current M5/M15 closes; defended parent bars can set lowerTFConfirmed. Proximity is as wide as 0.75 ATR and entry accepts earlier M1/M5/M15 extremes. | New engine requires actual Bid touches with points tolerance and correct approach. Optional existing lower-TF requirement is checked independently using completed M5/M15 rejection candles after OB confirmation. It can legitimately prevent first touches; no assertion that USDCHF was blocked by it without logs. |
| No explicit continuation/role-flip sequence; TRIGGERED bypasses several gates. | Persist one mode per setup; no fallback. Explicit breakout interpretation starts UNSELECTED (disabled). Separate role-flip ID; original retired first. Rejection-close is a documented new default. |
| InpMaxSpikeAtrMultiplier, InpEnableSessionShield, InpEnableSpreadGuard and InpEnableForexCryptoConfluence declared but not used as executable entry controls. No economic-calendar/news feed restriction exists. | Put operational session/spread controls and live M1 range/gap shock cooldown in shared final gate. Preserve broker/cash session and circuit breaker. Price-shock protection does not claim to forecast scheduled news. |
| Auto path resets g_currentTradeTaken and deletes completed/pending keys if no position is visible; uncertain/partial execution can lose its lock. Multi-leg legacy path excludes DONE_PARTIAL. | Durable submission reservation for precision setups, broker-history/event reconciliation and permanent consumed IDs. Partial/uncertain results stop further legs, retain protective stops, never blindly retry. Legacy key deletion removed. |
| Portfolio cap uses MathMax(24, configured limit), ignoring a smaller ceiling. Smart micro-account floor can exceed intended cash risk; sizing models BUY even for SELL. | Enforce the configured lower ceilings. Precision sizing uses actual BUY/SELL entry/SL with OrderCalcProfit, aggregate setup budget and floor rounding; skip if broker minimum exceeds budget. Fixed lots capped by the same configured risk profile. |
| Legacy recalculates targets to force them farther away at execution; delayed entries can change R:R. | Precision freezes structural targets when armed, rechecks at current executable quote; no target chasing or stop removal. Preserve structural stop selector and management/exit routines. |
| No advisor BuyLimit/SellLimit placement exists. Generic pending activation can convert any order to market. Manual-master cloning initially sends no stops. | Precision only submits protected market requests after its event. Cancel advisor pending orders on its symbol before entries; cancellation failure blocks. Generic activation cannot bypass advisor precision sequencing. Keep manual tools separate but route their new orders through the common gate with protection validation. |
| Terminal globals/snapshots and position-group reconstruction already exist. | Add account/symbol-scoped durable precision catalog and setup fields; reconcile broker positions, orders and history before accepting entries; expire interrupted unsubmitted sequences rather than invent missing ticks. Preserve existing exits, healing, trailing, breakeven, UI, account sync and signal snapshots. |

Execution review includes advisor market orders, manual-master clones, generic pending activation, and SafePositionClose (an exit, not an entry). No essential strategy source file is missing. MetaEditor/terminal, broker tick history, the referenced USDCHF screenshot and its Experts/Journal logs are absent; native compilation, actual fills and that incident cannot be verified here.
