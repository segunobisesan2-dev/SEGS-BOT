SEGS Trade Manager Pro v3.78 — stack overflow fix

Evidence: the supplied screenshot shows rapid repeated USDJPY pullback-touch messages followed by "stack overflow" in SEGS_Trade_Manager_Pro_v3.71.mq5. This establishes an EA stack failure, not proof that the entire terminal exited.

Root cause confirmed in source: DrawSentimentHUD calls ScanMarketStructureAndAdvice; the scanner calls DrawSentimentHUD on the level-touch path. Further cycles run through RefreshAccountAdvisorState and ExecuteAdvisedTrade. Repeated nested calls can exhaust the stack before any order executes.

Fixes:
- HUD drawing uses the latest strategy snapshot and never calls the scanner.
- All eight auto-execution calls inside the scanner are removed. RunAdvisorStrategyEngine performs automatic execution once, after scanning/calibration, when allowAutoTrade is true.
- Added scoped guards to engine, scanner, HUD, auto-check and execution callbacks. Guards release ownership on every normal early return. Nested calls cannot enter an already active callback.
- Touch promotion logging occurs on a transition into TRIGGERED, rather than repeating while that state persists.
- The v3.77 supply/demand role reversal and restart hardening remain included.
