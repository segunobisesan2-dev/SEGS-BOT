# SEGS.mq5 v3.81 — active entries and planned entries

The NDAQ screenshot shows real advisor positions at 93.54 while the candidate signal is a restored ID. v3.80 classified display status using the current-version signal hash, so an older open trade could be labeled PLANNED ENTRY and paired with the contradictory message NO ACTIVE TRADE OPENED. This was a display-state defect; changing execution deduplication back to 'any open position means the current signal executed' would have broken independent second setups.

v3.81 uses a separate, read-only snapshot of actual broker positions for display. Exact broker symbol plus advisor magic/recognized advisor comment determines ownership. Old-version tags, an empty or unrelated current signal, a restart/recompile, a stale feed, or a circuit breaker cannot convert a still-open position into a plan. It remains ACTIVE ENTRY until its actual broker position closes. A pending request or strategy TRIGGERED flag alone is never a fill.

The HUD now lists actual active BUY/SELL entries and their broker SL independently from NEXT PLANNED ENTRY. Distinct setup identities/directions stay separate, and different leg fill prices are shown as a range rather than a fictitious average. Up to two groups fit in the HUD; any further groups are explicitly signposted and have per-ticket chart markings. Legacy positions without a recoverable group ID are not guessed to be one setup. The header therefore reports the actual number of open positions rather than presenting an uncertain legacy group count as a confirmed setup count.

Chart labels draw actual fills under a dedicated ACTIVE_ENTRY namespace. Candidate lines remain NEXT PLANNED ENTRY / PLANNED SL. Their lifecycle is separate: clearing a plan cannot delete an active-entry label; closed positions disappear from the next broker snapshot. Existing open-trade markings also explicitly say ACTIVE ENTRY. Both display paths use the exact symbol rather than merging category aliases. Restored/consumed candidate snapshots cannot create a phantom plan, while a genuinely new independent candidate can coexist with older active positions.

Display changes do not overwrite candidate execution globals, modify broker orders/stops/targets, relax reversal/entry gates, or reinstate the old single-position entry veto. The v3.80 bounded dual-stop policy and two-setup default remain intact. When history is not yet synchronized, the active-entry line can still be drawn directly from broker positions; quote/history readiness continues to gate new entries.

Validation: 18 assertions execute the extracted broker display resolver with C++ stubs, covering the NDAQ legacy/restored-ID case, empty current ID, simultaneous active/next planned entries, in-flight/TRIGGERED without a fill, filled and closed candidates, separate directions/symbols, unequal fill prices, partial/full closure and unrelated manual positions. Read-only source assertions ensure the collector does not depend on live quote freshness or call trading/healing routines. Existing stop, second-setup/system-setting, entry-policy, expiry, lexical/source synchronization and 40,000-deal history checks pass. No native MetaEditor compiler or MT5 UI runtime is available here, so native compilation and chart validation remain required.

Use the updated contents in the existing SEGS.mq5 source and press F7. Successful compilation of the same attached EA filename causes MT5 to reload it; removing the attached EA is not required. On demo, verify the existing NDAQ trade says ACTIVE ENTRY at its broker fill, a separate new candidate says NEXT PLANNED ENTRY, stale feed only pauses new entries, and partial/full closure updates the active labels correctly.
